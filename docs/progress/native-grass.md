### What Arena's grass is, and where its data lives
- Arena's Grass scene (`Arena_Yard_Grass` in the port; three empty GameObjects after the import) carries two `GPUInstancerPrefabManager` (normal camera and optic camera) and a `GrassInitialization` component. [read, work/tmp/yard-grass/reports/G2]
- Placement: `StreamingAssets/Grass/ArenaGrassPrefabs_Yard.pcl`. No header; 68 bytes per clump (an int slice index and a 4x4 matrix, column-major, translation in floats 12 to 14); the count is the file length / 68. [read, GrassPrefabData.cs and GrassInitialization.cs; measured]
- Yard's file: 688,976 B = 10,132 clumps; slice histogram 0/8/8103/1457/564; x -66.95..9.23, y 5.90..6.30, z 17.39..117.81; scale 0.184..1.124; yaw-only. [measured on Arena 0.6.2.0.48473, by `NativeGrassRealDataTests` and `tools/tests/test_grass_art_ranges.py`]
- Art: `sharedassets95.assets.resS` (11,185,040 B) holds `Grass_new_1_N` (DXT1, 1024 x 1024, 11 mips, offset 0, 699,064 B), `GrassTexArray` (DXT5, 5 slices, offset 699,072, 6,990,640 B) and `GrassNormalArray` (DXT1, offset 7,689,712, 3,495,320 B). `sharedassets95.assets` is 13,940 B. Order is slice-major with the whole mip chain per slice; the 4x4, 2x2 and 1x1 mips are padded to one block. [measured: UnityPy typetree and the mip-chain coherence test]
- Values (colour lists, prototype, material floats, LODs, meshes) come from Arena's typetrees and are pinned in `NativeGrassColorModel.cs`; the meshes are generated by a rule that reproduces Arena's decode (positions and uvs within 4e-7, normals, tangents and indices exactly). [measured offline; reviewer re-derived all of them independently]
- EFT 0.16.9.5 ships the same GPUInstancer runtime and the real `GPUInstancer/Foliage_Simple` shader (Streets and Ground Zero use it). [read, `D:/SPT41/Development/_decompiled/GPUInstancer/`]

### Why the client builds it, and why the art comes from the player's own Arena files
Shape E: no bundle, package, descriptor, staging or packer change; `dist/` stays as it is. The other shapes were rejected:
- Serialized managers in a bundle (C): they wake before `ShaderRebind` and clone materials by shader NAME; the port's stand-ins are `Hidden/ArenaMapPort/...`, so the clone lands on Standard (quads at the world origin, Warning "Can not find instanced shader"). [read, G1]
- A new package and bundle-side art (C'): 25 minutes of Unity build and about 1.4 GB of sync per iteration, a Texture2DArray import path, normal-texture policy rows for the `Foliage_Simple` slots, and a `yard-native-v3`.
- A plaintext side package of the arrays (D'): refused. The arrays overlap the sampled blocks of `sharedassets95.assets.resS` that stage 2 derives its key from (`check_not_key_source`), and a decoded copy contradicts item 23's "no plain decoded copy ships".

### Build order (requirement; each step read from the decompile)
0. Worker: gate `State == Verified`, folder = `Result.InstallPath`, never a blocking call (a source pin forbids `EnsureVerified`); placement parse, `CheckRanges`, both file sizes, one bounded read per range, `CheckBlocks`; 30 s watchdog. NotStarted, Running and TimedOut are pending; any other gate state is the refusal `arena:<State>`.
1. Shader from the `shaderBindings.shaderInstances` row `GPUInstancer/Foliage_Simple` (path `bindings-row`), `Shader.Find` only as fallback; noise from `Resources.Load("Textures/Noise/Fractal_Simplex_grayscale")`, else procedural. Deviation from the design text: `GetInstancedShader(name)` is not called because on a miss it logs a Warning and silently returns Standard [read GPUInstancerShaderBindings.cs 121-164]; the row scan is the same lookup without that side effect.
2. Textures: arrays created through the `GraphicsFormat` constructor with `MipChain | IgnoreMipmapLimit`, uploaded per (slice, mip) by `SetPixelData` or per slice through a temporary Texture2D and `CopyTexture`; the plain normal texture by `LoadRawTextureData`; buffers dropped. Deviation from the design: Unity 2022.3's `Texture2DArray` has no `ignoreMipmapLimit` property, so the flag goes through the creation flags and the result is verified (a limited array fails the build naming the mip limit). Arena's serialized GraphicsFormat 97 (`RGB_DXT1_UNorm`) is obsolete (compile error) in this Unity; `RGBA_DXT1_UNorm` (the same BC1 block) is used. [read from UnityEngine.CoreModule metadata; the engine treating both alike is unknown]
3. Two generated meshes, two materials from the real shader with every property of Arena's, a prefab root (inactive, layer 31) with a LODGroup of two LODs, moved into the Grass scene.
4. Holder created INACTIVE in the Grass scene (`MoveGameObjectToScene`, never DontDestroyOnLoad), both `GPUInstancerPrefabManager` added (second `IsOptic`), cameras and prior HiZ presence recorded.
5. `SetActive(true)` then a wake-up check (the engine swallows Awake exceptions [GPUInstancerManager.cs 273-330]).
6. `DefineGameObjectAsPrefabPrototypeAtRuntime` on the normal then the optic manager; the same prototype is required [GPUInstancerPrefabManager.cs 1135-1160, GPUInstancerUtility.cs 1476-1536].
7. Every prototype field before the first instance call; then `enableRuntimeModifications = true` as `GrassInitialization` does.
8. Per manager, `GrassInitialization.Awake`'s order [GrassInitialization.cs 40-66]: `SetColorBuffers` (summer lists only), `InitializeWithMatrix4x4Array`, `SetInstanceCount`, `DefineAndAddVariationFromArray<int>("_ArrayIndexBuffer")`.
9. The cloned materials are checked to sit on the real shader (a Standard clone fails the build).
10. Motion-vector command-buffer fix-up (a requirement, not a suggestion): `Awake` sets `isMotionVectorsInit`, and `CreateMotionVectorsData` starts with `DisposeMotionVectorsData`, which resets the flag and releases the static buffers, so the second manager's Awake repeats the block and releases the first manager's buffers while they are attached [read GPUInstancerManager.cs 273-282, 404-406, 598-646]. Stale buffers of the four names (`MotionVectorsPASS`, `MotionVectorsAfterPASS`, `MotionVectorsOpticPASS`, `MotionVectorsAfterOpticPASS`) are removed (identity by managed reference or the native `m_Ptr`, because `GetCommandBuffers` may hand out wrappers), then `InitializeCameraData()` on both managers; before and after are logged by name.
11. The Drawing key is applied; context, summary and layer lines are logged.

State machine (Unity-free, unit-tested): a Build only with the map's scenes loaded, the game camera AND the optic camera present for 30 ticks of the same camera instances (a port-chosen number), not Stopping, the worker's inputs ready; never in the tick of or after a teardown (one-tick gap).

### Lifecycle contract
Both managers are created and destroyed together (the motion-vector buffers are process-wide). Teardown reasons: KeyOff, RaidEnded, ScenesUnloaded, CameraLost, CameraReplaced, GameStopping, ConfigChanged, Failure; the unload of any owned scene runs one `TickCore()` at once. Teardown removes the named command buffers from every camera the build or a replacement touched, destroys the HiZ component and its depth-blit material only where the build (or its managers) added it, destroys both managers (`DestroyImmediate`), the clones, the colour buffers, the prototype, the prefab root, the holder, the materials, meshes and textures. It is idempotent, every step in its own try. A failure latches for the session with ONE Warning and an immediate teardown; later raids log Debug. A vanilla raid and the hideout after a Yard raid must find nothing of it.

### Log lines (all Debug, tag `[Grass]`, no Info line, one Warning per session)
`keys bound`, `state:` (each change), `worker started`, `inputs:` (art, checks, placement size, records, slice histogram, extent, bytes read, worker ms), `shader:` (path, name, noise path), `upload:` (path, formats, mips, mipLimit, ms), `prefab:`, `managers:` (ids, activeManagers, scene, cameras, HiZ before), `prototype:` (clones all on the real shader, instances, ms), `commandBuffers:` (before, removedStale, after; fix-up ms; HiZ after), `context:` (GrassShadow, TAA, SSR, frame limiter, vsync, motion vectors, screen, lodBias, shadowDistance, mipLimit, frame stamp), `built in <ms> ms on the main thread`, `layers:` (layer 31 in the game and optic camera masks, each active directional light's mask and shadows, ms; added by the review, logged after the cost line because it does one light search), `drawing on|off`, `teardown reason=...`, and the one Warning `no native grass: <reason>`; `no grass this raid, latched: <reason>` at Debug; `tick failed, no more ticks until the next raid: <exception>` at Debug.

### Review: what was applied and what was rejected
Three reviews (runtime, data, rules and tests) found no blocker. Checked against the decompile and the files, 2026-11-21:
- Applied (medium): teardown after a mid-raid camera replacement left the named buffers and a new HiZ component on the NEW camera, because the managers' `Update` self-heals (`InitializeCameraData`, `SetupOcclusionCulling`) before the glue's teardown [read GPUInstancerManager.cs 574-577, 818-835]. Teardown now cleans the recorded cameras, the managers' current cameras and CameraManager's current cameras, and destroys a HiZ on a replacement camera only when one of the managers points at it. The camera serial now includes the optic camera instance (`OpticCameraManager.Init` re-creates it).
- Applied (medium): the `layers:` line (layer 31 in the camera masks and the suns).
- Applied (low): a throwing tick latched and logged every frame; now it logs once, stops ticking until the next raid and tears down quietly. The HiZ component's private `_depthBlitMaterial` (made in `OnEnable`, never freed in `OnDestroy` [read GPUInstancerHiZOcclusionGenerator.cs 65-72, 104-124]) is destroyed with it. Gate state `TimedOut` is pending, not a refusal. The mip-limit exception is no longer caught by the SetPixelData-to-CopyTexture fallback (`GrassMipLimitException`). Comment and wording fixes: slice 0 holds none and slice 1 holds 8 clumps; `Linear` is the import's sRGB flag and is never read; the mesh match is within 4e-7, not 0.0; the wave-normal path exists in EFT's Resources container (resources.assets 832) and is no longer called inferred.
- Rejected (low): making the placement file's 688,976 B a runtime size pin. The lead's rule names pinned sizes for the art; the placement is guarded by divisibility by 68, a count range of 8,000 to 12,500, finite affine matrices, scale range, slice range and the position box, which also catches a changed layout. A hotfix that moved the placement file would show as a refused count or box rather than silently wrong grass; a size pin would only turn a harmless size change into no grass. Recorded here so the lead can reverse it.
- Not changed, for the lead: the keys do not check `DeveloperMode` (decision 4, see above); `NotStarted` is a permanent gate state (Initialize failed or never ran) and the probe then waits forever without a Warning (the gate reports its own failure elsewhere).
- Test gaps: `RangeOutsideFile` and `RangeArithmetic` have no test by name (the ranges are constants; reaching them needs a faked table); the glue is covered by order and presence pins, not behaviour. Five pins were added for the applied findings.
- Port-chosen numbers, not Arena's: 30 ready ticks, 30 s worker timeout, 500,000 record cap, affine tolerance 1e-4, mean block difference bound 2.0, the Yard box margins and count range, the placeholder blade geometry, the procedural noise fallback.

### What changed against stage 1, and why
- Stage 1 read the placement and the art from the player's verified Arena folder at raid time (shape E). Stage 2 reads neither: the build machine reads Arena once, writes a **grass pack** per map, and the staging step encrypts it as `bundles/<map_key>_grass.bundle` (AMPB, the map's own content key, no new key wrap, no new key file). - The pack carries that map's placement and its own copy of the three art ranges (11,185,024 B of art per map). Pack sizes: Bowl 18,913,020 B, Iceberg 12,233,176 B, Yard 11,874,272 B (about 43 MB plaintext; AMPB adds a header and per-chunk integrity data).

### The grass pack, format version 1 (AMGP; little-endian; Python writer `tools/extract/grass_pack.py`, C# reader `ArenaMapPort.Client/NativeGrassPackModel.cs`, third reader `validate_distribution.parse_grass_pack_header`; all three pinned equal by tests)
- offset 0: ASCII `AMGP`; 4: uint32 version = 1; 8: uint32 header size = 272; 12: uint32 entry count = 4; 16: 32 bytes map key in ASCII, zero-padded; 48: four entries of 56 bytes.
- Entry: kind, format, width, height, slices, mips, filter, wrap, aniso, reserved (= 0) as uint32 (40 bytes), then uint64 offset (absolute) and uint64 size. Kinds in this order: 1 placement records, 2 albedo array (`GrassTexArray`), 3 normal array (`GrassNormalArray`), 4 normal texture (`Grass_new_1_N`). Formats: 0 records, 1 DXT1, 5 DXT5 (the C# `GrassBlockFormat` enum is 0 and 1: the reader maps the id to a block size, it does not reuse the number). Placement entry: width = record size 68, height = record count, slices = the albedo's slice count, mips 0.
- Payloads follow the header contiguously in entry order, no padding; file length = last offset + last size. Placement = Arena's `.pcl` byte for byte. A texture = Arena's stream range byte for byte: slice-major, each slice's whole mip chain down to 1 x 1, mips smaller than a block padded to one block; the size is the arithmetic of `NativeGrassArtModel` (the pack tool and the reader share it).
- The reader refuses anything else, with one code per cause (the same names in Python and C#): TooShort, BadMagic, BadVersion, BadHeaderSize, BadEntryCount, BadMapKey, MapKeyMismatch, KindOrder, BadFormat, ReservedNotZero, BadPlacementShape, BadTextureShape, SizeMismatch, Inconsistent (placement or normal-array slices differ from the albedo's), NotContiguous, FileLength. The C# reader also refuses a texture payload of 2 GiB or more. The 800-byte synthetic vector (map key `arena_test`) is pinned in both test suites.
- Measured on Arena 0.6.2.0.48473 (art pins in `extract_grass.ART_PINS`; a difference stops the tool with "Arena changed"): Bowl 113,643 records, slices 0/26,265/62,125/11,315/13,938, scale 0.055..1.403, tilt up to 2.6 degrees; Iceberg 15,410, 6/1,064/6,357/1,301/6,682, scale 0.120..2.236, tilt up to 50.0 degrees, non-uniform up to 0.75; Yard 10,132, 0/8/8,103/1,457/564, scale 0.184..1.124, tilt 0. Art per pack: 6,990,640 + 3,495,320 + 699,064 B. Level files: Bowl level95, Iceberg level260, Yard level162.
- The summer colour lists of Bowl and Iceberg equal the constants in `NativeGrassColorModel.cs` (the pack tool compares float for float and fails loudly otherwise), so the season rule stays "Arena's summer lists always" and no per-map constants exist.

### Failure policy
A map without its grass still plays. A refusal is per map: the state machine answers `InputsRefused`, the glue keeps `_refused[mapKey]`, the key flag then reads "not wanted", ONE Warning per session and map with a reason code, Debug afterwards. A missing bundle logs Debug in the glue because `Plugin` already warns at startup (`Required map file is missing: ...<key>_grass.bundle`; kept deliberately: once per start and map, the map plays, the grass has no switch for a file that is not there). Only an exception of the build or the tick latches the session (one Warning, Debug afterwards, shared across maps because the cause is engine-side). No Info line. The map's own bundles, the notices, the server and `MapLoadFailures` never see the grass bundle (the existing opener `BundleKeyResolver.Prepare` is deliberately not used: it logs Errors and writes failure records).
Reason codes (the exception TYPE only, never a message or path): `pack-missing`, `pack-unreadable:<ExceptionType>`, `key-unavailable`, `container:<AmpbError>` (HeaderAuth, WrongMap, Truncated, BadHeader, BadVersion, ChunkIntegrity), `pack-format:<GrassPackError>`, `placement:<GrassPlacementError>[@record]` or `placement:ShortRead`, `art-read:<range>:ShortRead`, `art-blocks:<range>:<ConstantData|MipChainIncoherent|ShortRead>`, `io:<ExceptionType>`, `worker:timeout`, `worker:abandoned`, `worker:faulted`, `worker:NoResult`; engine-side `build: <Type>` and `tick: <Type>`.
Thread map: the game thread opens the file, checks the AMPB magic, takes the map's key by a **non-blocking peek** (`BundleKeyResolver.TryPeekKey`: a cache hit only, no gate call, no derivation, no log) and a copy of it, and picks the crypto provider; the worker (LongRunning, no Unity type, never logs) opens `AmpbReadStream` with the copy, clears the copy, parses the header, reads the placement and the three art ranges (with the structure check), disposes the stream; the tick polls with a 30 s watchdog. A plain pack (a development build) is read directly.

## 2026-11-22 - Wind: the grass sways (the author's observation, the cause, the repair, the host run)

**The author's observation (user, 2026-11-22, after looking at the game on the author's own PC):** "Block passt, Regentropfen auch, mir fiel aber gerade auf dass das Gras sich nicht im Wind bewegt, bekommen wir das auch noch hin? beim drüberlaufen wird es zumindest platt gedrückt". **Cause (established).**
- EFT's `GPUInstancer/Foliage_Simple` (resources.assets, path id 2053, DX11) has vertex wind code in every draw pass (disassembled). It reads no `_Time`; its only time-varying input is the GLOBAL vector `_WindTimeScaledVector` (cbuffer EachFrameUpdate), which scrolls the lookup into `_WindWaveNormalTexture`. The global `_WindVector` gives direction and strength; the material's `_WindIdleSway` 0.3, `_WindWaveSway` 0.15 and `_WindWavesOn` 1 (ours equal Arena's and EFT's own Streets material) scale the terms; the vertex weight is the object-space height. No keyword gates it; the shader has no colour input.
- **Correction of the stage-1 inference:** the stage-1 report G1 inferred from an identifier scan that the shader had no wind code. That was wrong. No comment in the grass files said so.
- In EFT 0.16.9.5 only `EFT.Weather.WindCalculator.SetupFoliage` advances `_WindTimeScaledVector` and `_PrevWindTimeScaledVector` (`Camera.onPreCull`, for every culling camera: `phase += Time.deltaTime * factor`; factor from `WindCalculator.SetWind`: `(wind + 0.3) * -0.020000001 * (|wind| + 6 * 0.3)`). A calculator exists only after `WindController.SetWind(TreeWind.Settings[])` with a non-empty array (`LevelSettings.ApplyTreeWindSettings`); a ported scene has no TreeWind settings (EFT's own log says `Invalid windSettings` once per raid on a ported map, bowl-release.md).
- Trampling is a different mechanism: the globals `_GrassPlayerPosition`, `_GrassPlayerDirection`, `_GrassValues` of EFT's `GrassTrampler`. On a ported map one exists: host, Block, `uibridge_inspect find GrassTrampler`: 1 found, `GameWorld/Effects/GrassWaver` in the DontDestroyOnLoad scene (EFT's GameWorld brings it). AGENTS.md's Traps entry about `TechnicalManagers` lists a GrassTrampler under Factory's root as something Arena's scenes lack: true for that root, but the trampling does not depend on it. This is why the author saw the grass pressed flat.
